The `timestamp.updated_at` value represents the **last modification time of the entire JSON file**.

Whenever ANY data inside a JSON file is:

* added
* removed
* modified
* reordered, if the data change is intentional

update that file's:

```text
timestamp.updated_at
```

Do NOT add `updated_at` to individual records.

For example, if `food-items.json` is modified:

```text
food-items.json
    ↓
update timestamp.updated_at
```

But if only `restaurants.json` changes:

```text
restaurants.json
    ↓
update timestamp.updated_at
```

Do NOT update timestamps in the other two JSON files unless they were also modified.

## Timestamp format

Always use UTC ISO-8601 format with milliseconds:

```text
YYYY-MM-DDTHH:mm:ss.sssZ
```

Example:

```text
2026-09-08T03:15:42.000Z
```

The `Z` is mandatory and indicates UTC.

Do NOT use local timezone timestamps.

## TypeScript types

Do not add `updated_at` to `RestaurantImage`, `FoodItem`, or `Restaurant`.

Instead create a reusable wrapper type:

```ts
type JsonDataset<T> = {
  timestamp: {
    updated_at: string;
  };
  data: T[];
};
```

Then the datasets should be represented as:

```ts
type RestaurantImageData = JsonDataset<RestaurantImage>;

type FoodItemData = JsonDataset<FoodItem>;

type RestaurantData = JsonDataset<Restaurant>;
```

The JSON structure must therefore always be:

```text
Dataset
├── timestamp
│   └── updated_at
└── data[]
```

This file-level timestamp design is intentional because the frontend will use the timestamp to determine whether a particular dataset has changed and whether its cached version needs to be refreshed.
